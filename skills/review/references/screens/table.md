# Table or list of records

Applies to: rows of records with sort, filter, selection, pages. Read with: `search.md` when there is a search box, `states-and-edge-data.md` S-01–S-06 and D-01–D-05.

| Code | Check | Level |
|---|---|---|
| TB-01 | Columns show what people use to find and compare a row; the identifying column comes first and is never cut without a way to read it | Must |
| TB-02 | The default sort is stated or obvious; sortable columns show the current direction | Should |
| TB-03 | Numbers right-aligned in the locale format; dates in the project format; units in the header | Should |
| TB-04 | Each row opens with one obvious target (the name or the whole row), not several competing links | Should |
| TB-05 | Row actions sit in the same place on every row; destructive ones are in a menu or confirmed | Must |
| TB-06 | Selection shows the count and the bulk actions; "select all" says whether it means this page or every result | Must |
| TB-07 | The total count is shown; paging or loading more says where you are | Should |
| TB-08 | Active filters are visible above the table and can be cleared one by one or all at once | Must |
| TB-09 | Empty first use and empty after a filter are different states (S-01, S-02) | Must |
| TB-10 | Narrow widths: the table scrolls inside its region with the first column fixed, or turns into cards that keep the key fields | Must |
| TB-11 | Sort, filter, page and scroll survive opening a row and coming Back | Should |
| TB-12 | The header stays visible on long tables | Nice |
| TB-13 | Status columns use the DS tag or badge with text, not colour alone | Must |
| TB-14 | Editable cells, when there are any, show that they are editable and save or cancel clearly | Should |
