# Settings

Applies to: personal preferences, account, organisation, integrations, billing. Read with: `form.md` for each group.

| Code | Check | Level |
|---|---|---|
| ST-01 | Settings are grouped by what people look for (Profile, Notifications, Security…), with a list or tabs that shows the groups | Must |
| ST-02 | One save model per page: either each change saves at once (with a confirmation) or one Save button for the group; never mixed without saying so | Must |
| ST-03 | Each setting says what it does in a short line; the effect of a switch is clear when it is on and when it is off | Must |
| ST-04 | Settings that affect others (the whole organisation) say so, and who can change them | Must |
| ST-05 | Settings the user cannot change are shown read-only with the reason, not hidden | Should |
| ST-06 | Dangerous actions (delete account, leave the organisation) are apart, at the end, and confirmed with the name typed or an extra step | Must |
| ST-07 | Unsaved changes are kept or warned about when switching groups | Should |
| ST-08 | Search across settings when there are many | Nice |
| ST-09 | Changing the password or email asks for the current password and says what happens next | Must |
| ST-10 | Each group has its own URL | Nice |
