# Package layout, README, size

## Layout

`<name>` = `kit.config.json > handoff.zipName` with `{pbi}` (default `Design - {pbi}`, e.g. `Design - PBI 1234`). One zip `<name>.zip` with one folder `<name>/`:

```
<name>/
  README.md                 name, version, date, DS version label, packager, how to open, file list, Figma board link
  AGENTS.md                 for agents: reading path per role, code conventions, grep labels (pkg.py finalize)
  prototype.html            single-file app (locked or hidden when (b)/(c)); multi-page: prototype/ instead
  prototype/                multi-page: pages, shared files, images, fonts; same relative paths as the app
  spec/                     Markdown spec (annotate): index.md, flows.md, <unit>.md, cross-page.md, archive.md
                            (the last two are named by kit.config.json > handoff.specFiles)
  design-spec.html          ONLY when someone needs a visual copy; generated from spec/, never edited by hand
  requirements/
    checklist-feature.csv   feature list (step 5)
    changelog.md            last 2 versions only; older ones are in packages already sent
    checklist-qc.csv
    flows.json              wireflow data (with a spec)
    spec-map.json           unit <-> screen map with confidence (with a spec)
  screens/screens.json      NO images: route (with the query of the last goto), how to reach (text + runnable steps), pins
                            (without style: styles are in the spec tables), exits, Figma link per screen
  assets/                   WebP images split out of base64 (img-<hash>.webp), shared by all pages
  attachments/              sample files (PDF, PPTX, DOCX, XLSX) after optimize_attachments.py
```

- Links inside `spec/` are relative. Never link a private URL of the source.
- Each screen in `spec/<unit>.md` is a `### S01 · <name>` section with the route, a "How to reach" line (label `annotate.line.reach`) and `Figma: [S01](<node link>)`. The screen table in `spec/index.md` has a Figma column instead of an image column.
- Screens that depend on the machine date (calendar, "today") may differ from the Figma capture: say so in `pkg.json > agents_note`.

## README: "Which file for what" (with a spec)

Write in the project language. Keep only rows for files the package has (drop `cross-page.md` for a single-page app).

| Writing the spec: need | File |
|---|---|
| Scope, units and screens, unmatched items, out of scope | `spec/index.md` |
| One unit: business rules, screens (route, how to reach, Figma link), design notes (components, tokens, states) | `spec/<unit>.md` |
| Feature list | `requirements/checklist-feature.csv` |
| Page changes and data between pages (multi-page) | `spec/cross-page.md` |
| See one screen | the screen's `route` in `screens/screens.json` on the package prototype, or its `figma` link |
| Ask an agent to write the spec | the agent reads `AGENTS.md` first |

| Making a wireflow: need | File |
|---|---|
| Flow steps as text (screen → action → screen, branches, needs confirmation), Mermaid | `spec/flows.md` |
| Image of each screen | the Figma wireflow board (link in README) |
| Flow data for tools | `requirements/flows.json`, `screens/screens.json` |
| Figma screens rebuilt with DS components and variables | ask an agent to run `mockup` with this package |
| Visual copy with images | `design-spec.html`: only on request, generated by the packager from the captures |

Add "How to open the prototype" (always for multi-page packages): serve the **package folder** over HTTP, not `prototype/`, because images split out of base64 live in `assets/` next to `prototype/` and pages load them with `../assets/…`: `cd "<name>" && python3 -m http.server 8000`, then open `http://localhost:8000/prototype/<entry>` (single file: `http://localhost:8000/prototype.html`). Pages share data through the browser, so `file://` may break. Routes in `screens/screens.json` are relative to the package folder.

README also states: zip size; JS is inlined in each HTML file (no `.js` files); sample images are WebP in `assets/`; size steps used; each attachment with purpose, size before → after, optimised or kept.

## Size target (`handoff.maxZipMB`, default 3 MB)

`optimize_package.py` exit code: 0 met, 1 over target, 2 `.js` still loaded. When over, reduce in this order and measure after each step:

1. Remove what kept pages do not load (pages, images, fonts, shared files); duplicate screens.
2. Smaller images: `--max-px 1280 --quality 72`, then `--max-px 960 --quality 70`. Check that text in images is still readable.
3. Attachments still large after `optimize_attachments.py`: leave out, put a download link in README.
4. Heavy sample data: **ask the user** before trimming it to what the feature uses. That changes the demo content.
5. Still over: tell the user the size per part and the largest part; propose sending by link instead of attachment.

Never: rename `.js` to another extension, password-protect the zip, split it, nest zips, encrypt or obfuscate code.

Canvas note: when `optimize_package.py` prints a canvas NOTE (export to PDF/image reads moved images), README says to open over HTTP and QC re-tests export.
