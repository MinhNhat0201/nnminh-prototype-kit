One path from requirement to handoff

Each step is a skill you can also run on its own.

  1. Set up

    Build a base design system if you have none, then pick the language, stack and design system. The first app is created for you.

    adoptkickoff

  2. Define

    Turn PM and BA requirements into open questions, delivery waves and a traceability matrix.

    define

  3. Prototype

    Build screens with design-system components only. It asks before it creates a new component or page.

    prototype

  4. Specify

    Write the spec with screen captures, pins and token-level style notes. Put the flows and screens on Figma.

    annotatewireflowmockup

  5. Hand off

    Pack one zip for BA, QC and developers, and draft the email. It never sends it.

    handoffshare

Say what you want. The kit picks the skill.

Start with brief and describe the job in plain words. It asks one or two questions, then routes the job to the right skill with a one-line plan.

/kit:brief  I want to prototype a task manager for our team

You can also call a skill by name (/kit:prototype), or just ask: “build the settings screen”, “package feature 1234 for QC”.

14 skills, one job each.

Each name links to the skill’s instructions on GitHub.

Start

brief
Understands a plain-language request and routes it to the right skill.
kickoff
Sets up a project: config, design-system link, stack, first app and a smoke test.
adopt
Builds a base design system from the shadcn preset and your brand colour, with Material 3 structure for mobile and tablet.

Plan and build

define
Splits requirements into units, writes questions for PM and BA, plans delivery waves with acceptance criteria.
prototype
Builds screens and flows from a request, a plan wave or a screenshot, using design-system components first.

Specify

annotate
Writes a Markdown spec per unit, with screen captures, pinned elements and styles mapped to token names.
wireflow
Builds a flow board on Figma from screen captures and updates it in place, so shared links keep working.
mockup
Rebuilds screens on Figma with auto layout, library components and variables, then checks the result automatically.

Deliver

handoff
One zip for BA, QC and developers: spec, QC checklist, changelog, AGENTS.md and a scoped prototype.
share
Drafts the handoff email with Figma and demo links. Draft only; you send it.

Keep the design system in step

review
Read-only audit of an app against the design system, with options to fix what it finds.
sync
Brings a new design-system version into your apps.
contribute
Reviews local components and proposes the good ones to the design system, with two approval gates.
document
Writes and maintains design-system docs and tokens.

No design system is hard-coded.

The kit reads two files, so the same skills work for any team. Write the profile by hand for the design system you already have, or let adopt make one.

kit.config.jsonin your project
{
  "language": "en",
  "stack": "html",
  "ds": "ds/acme",
  "apps": [{ "id": "acme-web", "type": "single" }]
}

Language, stack, apps, local-component prefix, handoff and email settings.

ds/<name>/ds.jsonin a design-system profile

Token prefix and roles, CSS bundle, theming attributes, version label and Figma libraries.

No design system yet? Start from shadcn. Make it yours.

adopt asks for a brand colour, a name, a radius and a font. It takes the look from shadcn and the structure from Material Design 3, so one profile covers web, mobile and tablet.

  • Contrast checked in light and darkEvery colour pair: 4.5:1 for text, 3:1 for icons and borders.
  • Layouts that fit the screenA side rail on tablet and desktop becomes a bottom tab bar on phones. Touch targets are 48 px.
  • About 30 componentsA library.html demo page, with tokens in CSS and in the W3C design-token format.
  • Ready for shadcn/ui and shadcn-vueTheir components pick up your design system’s colours and radius.
  • Figma and Flutter, if you want themPush variables and text styles to Figma. A Flutter theme is generated too.

You pick the brand colour and the prefix. The kit never picks them for you, and never lowers the contrast thresholds.

HTML, React or Vue.

Each app can use its own stack, so older HTML apps and new Vue apps can live in one repository. React and Vue builds come out as a single HTML file that opens from any folder.

html

The default. One file that opens anywhere, and light handoff packages.

react

Vite, TypeScript, Tailwind and shadcn/ui, themed by your design system.

vue

Vite, TypeScript, Tailwind and shadcn-vue, themed by your design system.

One package. Every role knows where to read.

No loose .js files in the zip, so mail filters let it through.

  • BAFeature list and a Markdown spec per unit.
  • QCA checklist per feature.
  • DevelopersAGENTS.md with reading paths per role, styles mapped to token names, and the prototype itself.
  • EveryoneA Figma flow board, the changelog and a drafted email.

Your team’s language.

Replies and generated documents follow kit.config.json > language. English and Vietnamese ship with the kit. To add a language, copy locales/en/ and translate the values.

Install

/plugin marketplace add MinhNhat0201/nnminh-prototype-kit
/plugin install kit@nnminh-prototype-kit

Requirements

  • Claude Code, Python 3.9+ and Node 18+
  • Playwright with Chromium, for screen capture and browser checks
  • Pillow, for image optimisation
  • The Figma connector, for wireflow, mockup and the Figma step of adopt
  • A mail connector, for share
